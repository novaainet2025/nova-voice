# NOVA VOICE — 새 기능 설명서

이 세션에서 추가·변경된 기능만 정리한다. 모든 수치는 실측값이다.

관련 커밋: `476d9de1` · `28d203a2` · `aa8eb80f`

---

## 1. 단축키 — 모드가 나뉘었다

| 단축키 | 동작 |
|---|---|
| `⌃ ⇧ Space` | 일반 받아쓰기 — 인식한 문장을 그대로 입력 |
| `⌃ ⇧ ⌥ Space` | 메타 프롬프트 — 말한 요청을 다듬은 프롬프트로 입력 |
| `⌃ Esc` | 취소 (녹음 중·처리 중 모두) |

메타 단축키는 **그 한 번의 발화에만** 적용된다. 저장된 기본 모드는 바뀌지
않으므로, 평소 받아쓰기를 쓰다가 필요할 때만 눌러도 다음 녹음이 영향받지
않는다. 설정에서 바꿀 수 있고, 비우면 끈다.

---

## 2. 메타 프롬프트 — 정의가 바뀌었다

**전:** 요청을 AI가 대신 *수행*해서 완성된 답변을 입력했다.
**후:** 말한 요청을 다른 AI가 알아듣기 좋은 *프롬프트*로 다듬어 입력한다.

실측 예시 (qwen3:4b):

> **"지금 실행하고 있는 앱 리뷰한다"** (17자)
> → "지금 실행 중인 앱을 리뷰해 줘. 먼저 어떤 앱이고 어떤 상태로 떠 있는지
> 확인한 뒤, 실제로 동작을 확인할 수 있는 부분과 코드만 보고 판단한 부분을
> 구분해서 정리해 줘. …확인하지 못한 항목은 추측하지 말고 무엇을 더 봐야
> 하는지로 남겨 줘." (201자)

> **"이거 왜 느린지 좀 봐줘"** (13자) → 137자 프롬프트

CLI 맥락에서는 슬래시 명령 한 줄로 라우팅된다
(`/nco-discussion REST와 GraphQL 중 …`).

## 3. 응답 속도

### STT 실시간 스트리밍

말하는 동안 서버로 흘려보내, 녹음이 끝나는 시점에는 이미 인식이 끝나 있다.

| 12.3초 음성 | 녹음 종료 후 지연 |
|---|---|
| 기존 (일괄 업로드) | 541~838ms |
| 현재 (스트리밍) | **9~36ms** |

부수적으로 기존 버그도 고쳤다 — 일괄 업로드는 긴 음성에서 50% 확률로
45초 타임아웃했고, 성공해도 첫 문장만 남기고 나머지를 버렸다(81자 중 64자).

### 경량 모델 우선

메타 프롬프트는 문장 하나를 다듬는 가벼운 작업이다. 모델을 지정하지 않아
NCO가 각 프로바이더 기본값(claude-code는 frontier급 opus)을 쓰고 있었다.

- **로컬**: `qwen3:4b` 우선 → 없으면 `qwen3:14b`
- **NCO**: 각 프로바이더의 `workload=light` 모델 지정
  (claude-code→`haiku`, codex→`gpt-5.6-luna`, agy→`gemini-3.5-flash-low`)

로컬 실측: 웜 추론 1.6초, 메타 프롬프트 2.7~3.4초 (기존 14b 중앙값 13.1초).

### 서버 중복 제거

전과 달리 이미 모델을 물고 있는 서버를 재사용한다. 전에는 전용 서버를 따로
띄워 같은 14b를 이중 상주시켰다 — **25.6GB/48GB, 스왑 만재, free 86MB**.
정리 후 **free 13.6GB**.

### 자동 중지

기본 1.2초 → **0.9초**. 설정에서 0.7 / 0.9 / 1.2 / 1.6 / 2.0초 선택.

## 4. 프로바이더 자동 선택

`auto`가 codex 하드코딩이었다. 이제 NCO 실시간 상태(admission·큐·하트비트)와
앱이 직접 측정한 지연·성공률로 순위를 매기고, 실패하면 쿨다운을 기다리지 않고
다음 순위로 넘어간다.

판정 기준은 단순 지연이 아니라 **성공까지 걸리는 기대 시간**이다 — 1초에 70%
실패하는 쪽이 2초에 100% 성공하는 쪽보다 느리다.

**큐 포화 회피**: 포화된 프로바이더가 매번 1순위로 뽑혀 `queue_wait_timeout`
으로 10초를 버리고 있었다. 포화 페널티를 120으로 올려 해결했다.

설정 화면에 순위·사유·측정치가 그대로 보인다.

## 5. 입력 패턴 학습 (신규)

받아쓰기 이력에 **맥락**을 남기고, 거기서 두 가지를 배운다.

**별칭 자동 학습** — 말한 표현이 슬래시 명령으로 이어진 쌍을 센다. 같은 표현이
**3회 이상** 같은 명령으로 이어지면 별칭으로 인정해, 정적 카탈로그 205개가
놓치던 표현을 잡는다. (실측 라우팅률: 678건 중 15건 = 2.2%)

- 한 표현이 **서로 다른 명령**으로 이어지면 학습하지 않는다. 절반을 틀린 곳으로
  보내는 건 학습 안 하느니만 못하다.
- 한국어 STT는 같은 문장의 띄어쓰기가 매번 달라지므로 공백·문장부호를 지우고 센다.
- 4자 미만 표현은 배우지 않는다 (거의 모든 것에 매칭된다).

**앱별 습관** — 앱마다 자주 쓰는 명령·표현을 모아 메타 프롬프트 맥락에 넣는다.
앱 경계를 넘지 않는다.

**주입에 실패한 발화는 학습하지 않는다** — 사용자 의도를 말해주지 않기 때문이다.

새 DB 컬럼: `target_app` · `target_bundle_id` · `cli_target` ·
`is_slash_command` · `injected`

## 6. 음성 컴퓨터 제어 (신규)

말로 컴퓨터를 조작한다. **NOVA Use가 이미 제어 엔진**이므로 이 앱은 음성을
의도로 바꿔 보내는 쪽이 된다 — 제어 스택을 두 벌 만들지 않는다.

### 지금 동작하는 것

| 말하면 | 동작 |
|---|---|
| "파인더 열어줘" | 앱 실행 |
| "사파리로 전환" | 앱 전환 (없으면 실행) |
| "xxx 파일 찾아줘" | Spotlight 검색 (홈 폴더 한정) |
| "xxx 파일 보여줘" | Finder에서 표시 |
| "입력창에 포커스" | 앞 창의 첫 입력란에 커서 |
| "표 그려줘" | 마크다운 표 생성 |

### 아직 안 되는 것

- **클릭·타이핑·스크린샷** — 브리지 어댑터는 있으나 라우팅 전. 성공을 가장하지
  않고 "NOVA Use 연결이 필요합니다"라고 알린다.
- **이미지 생성** — 코드는 완성됐으나 codex 사용량 소진으로 **미검증**
  (2026-08-09 복구 예정)

### 안전 설계

허용 목록에 열거된 10개 동작만 실행된다. **자연어를 셸 명령으로 바꾸는 경로는
존재하지 않는다.**

검증한 차단 사례:
- `/etc/passwd` 등 홈 밖 경로 → 차단
- 홈 안 심볼릭 링크로 `/etc` 우회 → 차단 (경계 검사 전에 `realpath` 적용)
- `"Foo; rm -rf ~"` 앱 이름 → 거부 (셸 메타문자는 데이터로 남음)
- 허용 목록 밖 동작·잘못된 타입·초장문 입력 → 전부 거부

되돌릴 수 없는 동작(삭제·덮어쓰기)은 확인 UI가 생길 때까지 **실행하지 않는다**.
이때 결과는 `error`가 아니라 `refused`다 — 안전 판단이 오작동처럼 보이면 안 된다.

### 이미지 생성 (미검증)

Codex CLI의 네이티브 `imagegen` 도구를 쓴다. **API 키를 이 앱이 보관하지 않는다.**

모델을 `gpt-5.6-sol`로 고정한다. 기본 모델(`gpt-5.3-codex-spark`)에서는
`imagegen`이 붙지 않아 codex가 **조용히 PIL로 도형을 그리는 폴백**을 택한다.

생성 결과는 모델의 말이 아니라 **PNG 매직바이트를 직접 읽어** 검증한다.

표는 모델을 쓰지 않는다 — 결정적으로 만든다. 셀 안의 파이프는 이스케이프한다.

## 7. 안정성

### 창을 닫아도 동작한다

창을 닫으면 파형이 멈추고 메타 프롬프트도 안 됐다. 원인은 마이크를 잡고 있는
렌더러가 숨겨지면 `requestAnimationFrame`이 아예 멈추기 때문이다.

실측: 표시 상태 **120Hz → 숨김 0Hz**, `setInterval`도 32Hz → 1Hz.

그 루프 안에 "말이 끝났는지" 판정이 들어 있어서, 창을 닫으면 파형만 멈추는 게
아니라 **녹음이 영영 끝나지 않았다**. 두 창 모두 `backgroundThrottling: false`로
전환해 해결했다.

### 자동 복구

- 녹음 시작 후 **5초** 안에 오디오가 없으면 상태를 되돌리고 렌더러 재적재
- **180초** 초과 녹음 강제 종료
- 렌더러 사망·무응답 시 자동 리로드 (60초에 3회 넘으면 중단하고 원인 로그)

### 포커스 문제

받아쓰기가 엉뚱한 앱(터미널)으로 들어가던 문제를 고쳤다. 원인 두 가지:

1. 주입 대상을 처리 완료 후에 읽는데 2초 주기 폴러가 그 사이 덮어썼다
   → 녹음 시작 시점에 대상을 **래치**
2. NOVA Use처럼 dev 모드 Electron 앱은 프로세스 이름이 `Electron`이라
   NOVA VOICE가 **자기 자신으로 오인**했다 → **PID로 판별**

### 이전 대화가 입력되던 문제

주입은 클립보드를 빌려 쓰고 3초 뒤 되돌린다. 연달아 받아쓰면 앞 요청의 복원
타이머가 뒤 요청의 텍스트를 덮어썼다 → 주입마다 세대 번호를 매겨 최신 것만 복원.

단일 음량값으로 막대 높이를 곱하던 방식 → **캔버스 스펙트럼 분석기**

로그 간격 48밴드 좌우 대칭, 밴드별 어택/릴리스 엔벨로프, 감쇠 피크캡,
음량 연동 블룸, 모드별 팔레트(일반=청보라 / 메타=보라핑크).
React 리렌더 없이 자체 애니메이션 프레임에서 그린다.

## 검증 명령

```bash
npm run verify:all        # 아래 전부

npm run verify:core       # 정적 계약
npm run verify:latch      # 주입 대상 래치
npm run verify:learning   # 패턴 학습 (실제 SQLite)
npm run verify:computer   # 컴퓨터 제어 안전 경계 (실제 시스템)
npm run verify:providers  # 프로바이더 랭킹 (실제 NCO)
npm run verify:stt        # STT 스트리밍 (실제 Whisper 서버)
npm run verify:meta-ai    # 메타 프롬프트 품질 (실제 로컬 AI)
```

`verify:meta-ai`는 로컬 LLM을 쓰므로 다른 추론과 겹치지 않을 때 실행한다.

## 알려진 제약

- 컴퓨터 제어는 **macOS 전용**
- 클릭·타이핑·스크린샷은 NOVA Use 브리지 라우팅 전
- 이미지 생성은 codex 사용량 복구(2026-08-09) 후 검증 필요
- NOVA Use를 패키징하지 않고 실행하면 슬래시 명령 자동 실행이 동작하지 않는다
  (이름·번들로 CLI 대상 구분 불가)
